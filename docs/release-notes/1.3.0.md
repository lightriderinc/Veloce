## Veloce PQC SDK 1.3.0

**Cloud entropy from Lightrider EMS, live.** The agent now connects to the
Lightrider Entropy Management Service (`https://ems.lightriderinc.com`),
fetches signed randomness packets at a configurable interval, verifies each
receipt against the pinned service key (Ed25519, or ML-DSA-65 when the
service signs with it), checks freshness and the source health flags, and
mixes the packet into the FIPS random generator as the SP 800-90A
instantiation nonce at a DRBG re-instantiation. The hardware seed source
remains the only credited entropy; a cloud failure of any kind is recorded
and local operation continues. The fetch uses the FIPS module's own TLS
client with the Let's Encrypt root pinned, so no new library enters the
runtime. Off by default (zero network traffic): turn it on with the desktop
switch, or `veloce ems on` followed by `veloce mixin on`. The Free tier
works without an API key (`fastest_available` pool); `ems.api_key` unlocks
the higher pools.

**Entropy page for administrators.** The desktop Entropy page shows the
flow in plain words: hardware source, health checks, FIPS random generator,
keys and signatures, with the cloud feed as an optional extra input, each
with a Ready / Passing / Off state, plus one-line explanations. Technical
details (source kind, RBG construction, health-test parameters, strength
claim, mixing method) sit in a collapsed section for auditors.

**PQC provider.** Adds Ed25519 signature verification (RFC 8032, verify only)
for receipt checks, with a known-answer test in the provider gate and in the
agent self-test. `Ed25519 verify` is listed in the build record.

**Interfaces.** New agent operation `set_ems_mode`; new CLI command
`veloce ems on|off`; Python SDK `set_ems_mode`. Provider records for
`cloud-entropy-mixin` report endpoint, policy, verification algorithm,
packets mixed and rejected, last packet time, quality score, and last
error. Configuration keys: `ems.endpoint`, `ems.pubkey_hex`, `ems.policy`,
`ems.api_key`, `ems.ca_file`, `ems.interval_s`, `ems.bytes`,
`ems.max_age_s`, `ems.min_quality`.

Validation posture is unchanged: the cloud feed adds zero credited entropy,
carries no ESV claim, and does not alter the certificate #4718 position.
Downloads, verification, and licensing are as in 1.2.0.
